# Unslop

Make each sentence tell the reader something they can use or verify.
Edit only text in the requested scope and preserve its intended meaning.

- State the behavior, action or measured result directly. Replace claims such
  as "robust", "seamless" or "production-ready" with evidence, or remove them.
- Name the actor, source and condition. Avoid vague attribution and causal
  claims the repository or verification does not establish.
- Use plain verbs and stable domain names. Remove filler introductions,
  flattery, rhetorical contrasts and conclusions that repeat the paragraph.
- Keep one idea per sentence. Do not force a fixed number of bullets, decorate
  headings or invent jargon to make a small change sound architectural.
- Comments explain a non-obvious reason or constraint. Remove narration of
  the adjacent code and commented-out implementations.
- UI text names what happened and the available action. Do not expose internal
  implementation details unless they help the user decide what to do.
- Delivery and PR text describe the final change, exact checks and real limits.
  Do not claim independent review, accessibility conformance, measured speed
  or a deployment from evidence that only proves a different check.

PaperTok interface text and repository artifacts remain English. Preserve
paper titles, abstracts, quotations, attribution and original language;
this skill edits authored prose, not scientific evidence.
